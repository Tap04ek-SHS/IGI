# Lab5 Django Realty

Вариант 13: риэлтерское агентство. Проект реализует каталог объектов недвижимости, категории, владельцев, покупателей, сотрудников, продажи, новости, FAQ, вакансии, отзывы, промокоды, личный кабинет и API.

## Что закрыто по методичке

- Модели предметной области: объекты недвижимости, категории, владельцы, покупатели, сотрудники, продажи.
- Общие страницы: главная, о компании, новости, словарь, контакты, политика конфиденциальности, вакансии, отзывы, промокоды.
- Связи: `OneToOneField` для профилей, `ForeignKey` для владельцев/категорий/сотрудников/продаж, `ManyToManyField` для удобств и промокодов.
- CRUD для объектов недвижимости и продаж доступен сотрудникам/админу.
- Авторизация, регистрация, личный кабинет и разные права для гостя, клиента и сотрудника.
- Не менее 10 демо-объектов через `seed_data`.
- 2 внешних API: курсы НБ РБ и API времени. Сначала используется WorldTimeAPI, при его недоступности - TimeAPI.io.
- URL через `re_path` для детальных страниц.
- Статистика: сумма продаж, среднее, медиана, мода, возраст покупателей, популярная и прибыльная категория.
- Визуализация: таблица с нативной диаграммой `<progress>` по суммам продаж.
- Поиск, фильтрация и сортировка объектов.
- Валидация телефонов `+375 (29) XXX-XX-XX`, возраст 18+ для клиентов и сотрудников.
- API `/api/properties/` доступен только авторизованным пользователям.
- Logging с уровнем из `LOG_LEVEL`.
- Тесты Django.
- Dockerfile, docker-compose и production-настройки PostgreSQL.

## Локальный запуск

```bash
.venv/bin/pip install -r requirements.txt
.venv/bin/python manage.py migrate
.venv/bin/python manage.py seed_data
.venv/bin/python manage.py runserver
```

Сайт: `http://127.0.0.1:8000/`

Демо-пользователи после `seed_data`:

- `admin / admin12345` - superuser
- `agent / agent12345` - сотрудник с доступом к CRUD
- `client / client12345` - зарегистрированный клиент

## Картинки

Файлы можно загружать для тех сущностей, где картинки требуются по методичке:

- объекты недвижимости;
- новости;
- сотрудники на странице контактов;
- логотип компании на странице "О компании".

У этих сущностей есть два варианта картинки:

- `image` - загружаемый файл с компьютера;
- `image_url` - ссылка на картинку в интернете.

Приоритет такой: если загружен файл, показывается он; если файла нет, но есть `image_url`, показывается ссылка; если нет ни файла, ни ссылки, сайт сам генерирует SVG-заглушку по названию и категории объекта.

Как загрузить картинку:

1. Войти под `admin/admin12345` или `agent/agent12345`.
2. Открыть `http://127.0.0.1:8000/properties/`.
3. Нажать `Добавить объект` или `Изменить` у существующего объекта.
4. В поле `Загруженная картинка` выбрать файл.
5. Сохранить форму.

Альтернатива: в админке `http://127.0.0.1:8000/admin/` открыть нужный раздел:

- `Объекты недвижимости` -> блок `Картинка`;
- `Новости` -> блок `Картинка`;
- `Сотрудники` -> блок `Фото`;
- `Информация о компании` -> блок `Логотип`.

Для FAQ, вакансий, отзывов и промокодов картинки по методичке не требуются.

## Хостинг на Render

Проект подготовлен под Render: есть `build.sh`, `render.yaml`, `gunicorn`, `whitenoise`, PostgreSQL через `DATABASE_URL`.

### Вариант 1: Blueprint

1. Залить проект на GitHub.
2. В Render открыть `New` -> `Blueprint`.
3. Выбрать GitHub-репозиторий с этим проектом.
4. Render прочитает `render.yaml`, создаст Web Service и PostgreSQL.
5. После деплоя открыть URL вида `https://lab5-realty.onrender.com/`.

### Вариант 2: вручную

1. В Render создать PostgreSQL database.
2. Скопировать `Internal Database URL`.
3. Создать Web Service из GitHub-репозитория.
4. Указать:
   - Build Command: `./build.sh`
   - Start Command: `python manage.py migrate && python manage.py seed_data && gunicorn lab5.wsgi:application --bind 0.0.0.0:$PORT`
5. Добавить env vars:
   - `DEBUG=False`
   - `SECRET_KEY=<сгенерированный секрет>`
   - `DATABASE_URL=<Internal Database URL>`
   - `LOG_LEVEL=INFO`
   - `MEDIA_ROOT=/opt/render/project/src/media`
   - `SERVE_MEDIA=True`
6. После деплоя открыть Render Shell и при необходимости создать своего админа:

```bash
python manage.py createsuperuser
```

Важно про загруженные картинки на хостинге: для лабораторной можно оставить `SERVE_MEDIA=True`, и Django будет отдавать файлы из `MEDIA_ROOT`. Для настоящего production лучше использовать persistent disk плюс отдельную раздачу media или внешнее хранилище. Самый простой вариант для Render без настройки файлового хранилища - вставлять ссылку в `image_url`, потому что она хранится в PostgreSQL.
